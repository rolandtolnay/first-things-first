# Plan 01: Visual Reskin + Design System Polish

**Subsystem:** ui

## Context

This is the final MVP phase — transforming the functional-but-utilitarian interface into a calm, warm, professional design. This is a **pure visual reskin** — no component architecture changes, no drag-drop rewiring, no layout restructuring. Every existing component (DayColumn, TimeGrid, TimeBlock, DayPriorities, PriorityItem, EveningSlot) stays intact. All drag-drop logic, drop zone IDs, and store actions remain untouched.

The design token system comes from `.planning/phases/09-visual-polish/DESIGN-SYSTEM.md`. The per-component styling guide in DESIGN-SYSTEM.md sections 6.1-6.16 maps directly to existing components. When this plan describes tokens or values, cross-reference DESIGN-SYSTEM.md for exact values.

**Design spec adaptation:** The `09-DESIGN.md` proposed a band-grid architecture (replacing TimeGrid with horizontal bands). That architectural change is **dropped** — the per-day column layout with time slots stays. The visual design language from that spec (colors, typography, card styling, role-color backgrounds, shadows, radii) is applied to the existing component architecture instead. The `09-DESIGN.md` remains useful for token tables, sidebar mockups, WeekNavigation mockups, CarryoverDialog mockups, and goal card styling — ignore the BandGrid/BoardGoalCard sections.

Font changes from Geist Sans to Plus Jakarta Sans. Icon system changes from custom inline SVGs to Lucide React (already a project dependency).

Changes are ordered: tokens first, then layout shell, then components top-down (sidebar → navigation → calendar → dialog), then polish pass.

## Changes

### 1. Design token foundation
**Files:** `src/app/globals.css`

Overhaul the entire CSS custom property system. Replace the current HSL-based token set with the new palette from DESIGN-SYSTEM.md.

**Light mode (`:root`):** Replace existing tokens with new semantic names. Key tokens:
- Backgrounds: `--bg-page` (#F0FDFA teal-50 wash), `--bg-card` (#FFFFFF), `--bg-muted` (#F5F7FA), `--bg-hover` (#F0FDFA), `--bg-today` (rgba(20,184,166,0.04))

- Primary: `--primary` (#14B8A6), `--primary-hover` (#0D9488), `--primary-soft` (#CCFBF1), `--primary-muted` (#99F6E4)
- Semantic: `--success` (#10B981), `--warning` (#F59E0B), `--warning-soft` (#FEF3C7), `--destructive` (#EF4444)
- Borders: `--border-subtle` (#E2E8F0), `--border-emphasis` (#CBD5E1)

- Shadows: `--shadow-card` (0 2px 8px rgba(0,0,0,0.06), 0 1px 2px rgba(0,0,0,0.04)), `--shadow-sm`, `--shadow-drag`, `--shadow-dialog`

**Dark mode (`.dark`):** All dark counterparts from DESIGN-SYSTEM.md section 9. Key: bg-page #0F1419, bg-card #1A2332, primary #2DD4BF, shadows with higher opacity.

**Role colors:** Update `--role-1` through `--role-8` with refined palette from DESIGN-SYSTEM.md section 1 (Role Colors table). Store RGB components for opacity modifiers: `--role-1-rgb: 20,184,166`. Dark mode role colors use brighter variants.

**Tailwind v4 `@theme` integration:** Update the existing `@theme inline` block to expose new tokens to Tailwind utility classes. Map semantic tokens to Tailwind-consumable names where components use Tailwind classes (e.g., `--color-bg-page`, `--color-text-primary`).

Migrate existing token references incrementally — keep old tokens that are still referenced, remove once all consumers are updated.
