# Plan 01: Design System + Visual Reskin + Band Grid Architecture

**Subsystem:** ui

## Context

This is the final MVP phase — transforming the functional-but-utilitarian interface into a calm, warm, professional design. The work spans three tightly coupled layers: design token foundation, component reskinning, and a fundamental board layout change from per-day 24-slot TimeGrids to a 4-band sectioned grid (Priorities / Morning / Afternoon / Evening).

All visual specs come from two authoritative documents: `.planning/phases/09-visual-polish/DESIGN-SYSTEM.md` (comprehensive token system) and `.planning/phases/09-visual-polish/09-DESIGN.md` (per-component mockups and state tables). These are the source of truth for all color values, spacing, typography, and component behavior. When this plan describes tokens or values, always cross-reference those files for exact values.

The band grid is a presentation-only change — no data model modifications. Existing `dayPriorities`, `timeBlocks`, and `eveningBlocks` arrays map to the four bands by slot index ranges. The store actions (`addDayPriority`, `addTimeBlock`, `addEveningBlock`, etc.) remain unchanged.

Font changes from Geist Sans to Plus Jakarta Sans. Icon system changes from custom inline SVGs to Lucide React (already a project dependency).

Tasks are ordered by dependency chain: tokens first, then layout shell, then components that fill the shell, then integration (drag-drop), then polish pass.

## Changes

### 1. Design token foundation
**Files:** `src/app/globals.css`

Overhaul the entire CSS custom property system. Replace the current HSL-based token set with the new palette from `09-DESIGN.md` Design Tokens section.

**Light mode (`:root`):** Define all tokens from the Light Mode color table — `--bg-page` through `--completed-bg`. Include shadow tokens (`--shadow-card`, `--shadow-sm`, `--shadow-drag`, `--shadow-dialog`), radius tokens (`--radius-sm` 6px, `--radius-md` 10px, `--radius-lg` 14px, `--radius-xl` 20px, `--radius-full` 9999px), spacing tokens (page-pad, card-gap, etc.), animation duration tokens (`--duration-fast` 150ms, `--duration-normal` 200ms, `--duration-slow` 300ms).

**Dark mode (`.dark`):** Define all dark mode counterparts from the Dark Mode color table. Dark shadows use higher opacity values.

**Role colors:** Update `--role-1` through `--role-8` with values from the Role Colors table. Each role needs both a vibrant value (for borders, dots) and the base value. Store the RGB components so opacity modifiers work: e.g. `--role-1-rgb: 20,184,166` alongside `--role-1: #14B8A6`. Dark mode role colors use the Dark Vibrant column values.

**Existing Tailwind v4 `@theme` integration:** Ensure the new tokens integrate with how Tailwind v4 resolves CSS variables. The existing `@theme inline` block may need updating to expose new tokens to Tailwind's utility classes where needed.

Remove all old HSL-based tokens that are no longer referenced. Keep any that other unchanged components still consume, and migrate references incrementally.

### 3. Role color opacity helper
**Files:** `src/lib/role-colors.ts`

Add `getRoleColorStyleWithOpacity(color: RoleColor, opacity: number): string` that returns an `rgba(...)` string using the role color's RGB components at the given opacity. This uses the `--role-N-rgb` CSS variables defined in Change 1, reading them at runtime via `getComputedStyle` or by constructing the rgba string from known RGB values.

Keep all existing exports (`getRoleColorClass`, `getRoleColorIndex`, `getRoleColorStyle`) working. Update the color value mappings if the role color indices or values changed.

**From prior work:** Role color mapping uses `getRoleColorStyle()` for inline styles because Tailwind v4 purges dynamic classes. Continue this pattern — all runtime role colors must use inline styles, not dynamic class names.

### 7. BandGrid component (core architectural change)
**Files:** `src/components/calendar/BandGrid.tsx` (NEW), `src/components/calendar/DayHeader.tsx` (NEW), `src/components/calendar/BoardGoalCard.tsx` (NEW), `src/components/calendar/WeekView.tsx`

This replaces the per-day TimeGrid/DayColumn architecture with a single CSS Grid spanning all 7 days.

**DayHeader.tsx (NEW):**
- Day name: caption (12px/500), text-muted
- Date number: h2 (15px/600), text-secondary. Today: primary color + 700 weight
- Progress bar: 3px height, radius-full, border-subtle track, primary-muted fill. Width = completed/total % of all completable items across all bands for that day. Hidden when no items. CSS transition on width (300ms ease)
- Today column: bg-today background on the entire day header cell

**BandGrid.tsx (NEW):**
- CSS Grid: `grid-template-columns: 96px repeat(7, 1fr)`
- Row 1: Day header row — spacer cell (96px) + 7 DayHeader components
- Rows 2-5: 4 band rows — label cell + 7 band cells
- Band definitions per the Band Definitions table in `09-DESIGN.md`: Priorities (bg-muted, min-h 100px), Morning (bg-card, min-h 130px), Afternoon (bg-muted-alt, min-h 130px), Evening (bg-muted, min-h 100px)
- Band label column: 96px wide, 16px/12px padding, caption-bold (12px/600 uppercase 0.04em tracking), text-muted. Time bands show sub-label in caption (11px/400) with border-emphasis color
- Band cells: flex column, gap 6px, pad 8px/6px, align-items stretch
- Today column: bg-today applied to all cells in today's column index
- Column borders: 1px solid border-subtle between day columns (border-left on non-first columns)
- Band dividers: 1px solid border-subtle between band rows
- Bands expand to accommodate cards (min-height, not fixed height)
- Empty priority cells: "Drop goals here" in text-muted italic caption

**Data mapping (presentation only — NO data model changes):**
- `dayPriorities` array → Priorities band cards
- `timeBlocks` with `startSlot` 0-7 → Morning band cards
- `timeBlocks` with `startSlot` 8-15 → Afternoon band cards
- `timeBlocks` with `startSlot` 16-23 + `eveningBlocks` → Evening band cards
- Each card type maps to existing store actions for completion/deletion

**BoardGoalCard.tsx (NEW):**

- 10px/12px padding (board-card-pad)

- Checkbox: 16px CompletionCheckbox, RIGHT side, vertically centered
