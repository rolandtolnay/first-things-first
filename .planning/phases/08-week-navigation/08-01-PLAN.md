# Plan 01: Week Navigation and Creation

**Subsystem:** none | **Skills:** next-best-practices, vercel-composition-patterns, vercel-react-best-practices

## Context

The app currently auto-creates weeks on load and has no concept of navigating between weeks. This plan adds the complete multi-week workflow: refactoring the store to separate loading from creation, building a navigation header with arrows between existing weeks, creating a carryover dialog for intentional week creation, and wiring everything together in WeekView.

The architecture uses a Zustand + useLiveQuery hybrid: `selectedWeekId` in Zustand for synchronous navigation state, and `useLiveQuery(() => db.weeks.orderBy('id').primaryKeys())` from dexie-react-hooks for a reactive week index that auto-updates when weeks are created. Native `<dialog>` with `showModal()` provides the carryover dialog (focus trapping, backdrop, Esc dismissal built-in). No new dependencies are needed.

Key locked decisions from CONTEXT.md: arrows only navigate between existing weeks (no auto-creation), app opens to the most recent existing week with a banner when the current calendar week doesn't exist, past weeks are fully editable, roles always carry over silently (dialog only frames choice around goals), and first-ever open auto-creates the current week without dialog.

## Changes

### 1. Refactor weekStore — separate load from create, add navigation state
**Files:** `src/stores/weekStore.ts`

Add `selectedWeekId: WeekId | null` to the store state interface and initial state.

Refactor `loadWeek` (lines 174-191): Remove the auto-creation branch (lines 180-183). If `db.weeks.get(weekId)` returns undefined, set `currentWeek: null` and `isLoading: false` — do NOT call `createWeek`. Keep the try/catch error handling pattern.

Add `navigateToWeek(weekId: WeekId)`: Sets `selectedWeekId` synchronously via `set({ selectedWeekId: weekId })`, then calls `loadWeek(weekId)`. Include a stale-request guard: after the async `db.weeks.get()` resolves, check `get().selectedWeekId === weekId` before calling `set({ currentWeek })`. This prevents race conditions on rapid navigation.

Add `createNewWeek(weekId: WeekId, options: { carryOverGoals?: Goal[], sourceWeek?: Week })`:
1. Creates empty week via existing `createEmptyWeek(weekId, options.sourceWeek?.roles)` — this generates fresh role IDs.
2. If `carryOverGoals` is provided and non-empty, maps each goal to the new week by matching the goal's source role name to the new role (via `sourceWeek.roles` to find source role, then find new role with same name). Creates new Goal objects with `generateId()`, the matched new roleId, original text/notes, and `completed: false`.
3. Adds the mapped goals to the new week's `goals` array.
4. Saves via `saveWeek(week)`.
5. Returns the created week.

Update the store interface (`WeekStore`) to include `selectedWeekId`, `navigateToWeek`, and `createNewWeek` signatures.

**From prior work:** Carry-over with new IDs — fresh UUIDs prevent cross-week refs. `createEmptyWeek` accepts `carryOverRoles` and remaps IDs.

### 2. Create WeekNavigation header component
**Files:** `src/components/calendar/WeekNavigation.tsx`

Create a navigation header component with these props: `onNewWeek: () => void` (callback for parent to open carryover dialog).

Internal state and logic:
- `useLiveQuery(() => db.weeks.orderBy('id').primaryKeys(), [], [])` for reactive sorted week ID list.
- Read `selectedWeekId` from `useWeekStore`.
- Derive `canGoPrev` / `canGoNext` by finding the index of `selectedWeekId` in the sorted list and checking boundaries.
- Left arrow calls `navigateToWeek(previousExistingWeekId)`. Right arrow calls `navigateToWeek(nextExistingWeekId)`.
- Date range label using `formatWeekId(selectedWeekId)` from `src/lib/utils.ts`.
- "Today" button: If the current calendar week (`getCurrentWeekId()`) exists in the list, navigate there. Otherwise, navigate to the latest (last) existing week.
- "+New" button calls `onNewWeek` callback.
- Arrow buttons use the `disabled` attribute at boundaries.
- "This week" visual indicator (e.g., subtle badge or text) when `selectedWeekId === getCurrentWeekId()`.

Banner section below the navigation controls: Show when `existingWeekIds.length > 0 && !existingWeekIds.includes(getCurrentWeekId())`. Banner text: "Plan this week?" with a "Start" button that also calls `onNewWeek`. Style the banner with a highlighted/accent background to draw attention without blocking interaction.

Import `db` from `@/lib/db` and `useLiveQuery` from `dexie-react-hooks`.

### 3. Create CarryoverDialog component
**Files:** `src/components/calendar/CarryoverDialog.tsx`

Native `<dialog>` with controlled open/close pattern. Props: `open: boolean`, `onClose: () => void`, `sourceWeek: Week | null`.

Dialog open/close sync via `useEffect`:
- Guard: `if (open && !dialog.open) dialog.showModal()`, `if (!open && dialog.open) dialog.close()`.
- Handle `cancel` event (Esc key) — call `e.preventDefault()` then `onClose()`.

Content when `sourceWeek` is provided:
- Extract uncompleted goals: `sourceWeek.goals.filter(g => !g.completed)`.
- Group by role: for each role in `sourceWeek.roles`, find its uncompleted goals. Skip roles with zero uncompleted goals.
- Render as a checklist grouped by role: role name with a color dot/indicator using `getRoleColorStyle(role.color)` as inline style (import from `@/lib/role-colors`). Goals listed underneath as checkboxes.
- Use `CompletionCheckbox` from `@/components/ui/CompletionCheckbox` for the checkboxes (or a simpler native checkbox if the visual style doesn't fit — CompletionCheckbox is circular and might be confusing in a selection context; use a standard checkbox input with role-color accent instead).
- Local state: `Set<string>` of selected goalIds, initialized with all uncompleted goal IDs (all pre-selected by default). Toggle on checkbox click.
- "Carry Over Selected" button: calls `createNewWeek(getCurrentWeekId(), { carryOverGoals: selectedGoals, sourceWeek })` from the store, then `navigateToWeek(newWeekId)`, then `onClose()`.
- "Start Fresh" button: calls `createNewWeek(getCurrentWeekId(), { sourceWeek })` with no carryOverGoals (just roles), then `navigateToWeek(newWeekId)`, then `onClose()`.

Dialog styling: `backdrop:bg-black/50`, rounded corners, card background, adequate padding. The dialog should NOT mention roles as a concept — only present goals grouped by role for visual organization.

**From prior work:** Use inline styles via `getRoleColorStyle()` for role color indicators, not dynamic Tailwind classes (purged at build time).

### 4. Integrate navigation into WeekView
**Files:** `src/components/calendar/WeekView.tsx`

Replace the current hardcoded week loading with store-driven navigation:

1. Remove the `weekId` prop and the `getCurrentWeekId()` default. Instead, read `selectedWeekId` from `useWeekStore`.
2. On mount (useEffect), determine the initial week:
   - Check `db.weeks.count()`. If zero, auto-create the current week via `createNewWeek(getCurrentWeekId(), {})` from the store, then `navigateToWeek`.
   - If weeks exist, navigate to the latest existing week: `db.weeks.orderBy('id').reverse().limit(1).primaryKeys()` then `navigateToWeek(latestId)`.
3. Replace the existing "Week of ..." header (lines 34-42) with the `WeekNavigation` component. Pass `onNewWeek` callback that sets `isCarryoverOpen` state to true.
4. Add `CarryoverDialog` with `open={isCarryoverOpen}`, `onClose={() => setIsCarryoverOpen(false)}`, `sourceWeek={currentWeek}` (the currently displayed week serves as source for carryover).
5. Derive `dates` from `selectedWeekId` (via `getWeekDates`). Guard rendering: if `selectedWeekId` is null or `currentWeek` is null and not loading, show nothing or a minimal loading state.
6. The `useLiveQuery` in WeekNavigation auto-updates the week list when the dialog creates a new week — no manual cache invalidation needed.
