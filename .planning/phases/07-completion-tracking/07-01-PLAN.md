# Plan 01: Completion state and UI feedback

**Subsystem:** ui

## Context

Users need to track task completion with visual feedback across all four item types: goals (sidebar), day priorities, time blocks, and evening blocks. The data model is already prepared — `completed` boolean fields exist on Goal, TimeBlock, DayPriority, and EveningBlock, and all four toggle methods (`toggleGoalCompleted`, `toggleDayPriorityCompleted`, `toggleTimeBlockCompleted`, `toggleEveningBlockCompleted`) are already implemented in `src/stores/weekStore.ts`. The `--success` CSS variable (green) is defined in the theme. This plan is purely about surfacing existing state visually and wiring the toggle interaction.

A shared CompletionCheckbox component is created first, then integrated into each item type. The checkbox is always-visible (not hover-reveal) to differentiate from hover-reveal delete buttons. Completion is per-instance with no cross-instance sync.

## Changes

### 1. Create CompletionCheckbox component
**Files:** `src/components/ui/CompletionCheckbox.tsx`

Create a reusable CompletionCheckbox component with props: `completed: boolean`, `onToggle: () => void`, `size?: number` (default 14). Renders an inline SVG circle (empty when uncompleted) or circle with checkmark (when completed). Use `text-muted-foreground` for the uncompleted circle stroke, `hsl(var(--success))` for the completed checkmark and circle fill. Add a CSS transition on color/fill for smooth toggle feel. Apply `flex-shrink-0` to prevent layout shift.

The `onClick` handler calls `onToggle` with `e.stopPropagation()` to prevent triggering parent drag handlers. Use `onPointerDown` with `e.stopPropagation()` as well to prevent dnd-kit's PointerSensor from activating.

**From prior work:** Inline SVG icons pattern — no icon library dependency, consistent with CloseIcon approach in `src/components/ui/CloseIcon.tsx`.
**From prior work:** e.stopPropagation() prevents dnd-kit activation on interactive child elements (proven in resize handle).

### 2. Add completion UI to GoalItem
**Files:** `src/components/sidebar/GoalItem.tsx`

Import CompletionCheckbox and wire to `weekStore.toggleGoalCompleted(goal.id)`. Place the checkbox before the goal text in the flex layout. When `goal.completed` is true: apply green-tinted background using inline style `backgroundColor: 'hsl(var(--success) / 0.15)'`, and wrap the text content (not the whole row) in a container with `opacity-60`. The checkbox itself remains at full opacity for easy re-toggling. Keep the role-color left border unchanged (it uses inline styles via `getRoleColorStyle()`).

Do not show the checkbox during editing mode (`isEditing`). The checkbox is a separate click target from double-click-to-edit (the text span) and drag (the container), so no interaction conflict exists.

**From prior work:** Role colors use inline styles via getRoleColorStyle() — completed visual must layer green on top of existing inline role color styles. Use a combined inline style object.

### 3. Add completion UI to PriorityItem
**Files:** `src/components/calendar/PriorityItem.tsx`

Import CompletionCheckbox with `size={12}` for compact styling consistent with the existing `text-xs` text. Wire `onToggle` to `weekStore.toggleDayPriorityCompleted(priority.id)`. Place checkbox before the goal text. When `priority.completed` is true: apply green-tinted background `hsl(var(--success) / 0.15)` via inline style, and reduce text opacity to ~60%. Keep role-color left border unchanged. The checkbox `stopPropagation` prevents drag activation.

### 4. Add completion UI to TimeBlock
**Files:** `src/components/calendar/TimeBlock.tsx`

Import CompletionCheckbox and wire to `weekStore.toggleTimeBlockCompleted(block.id)`. Position the checkbox at the top-left area alongside the title. When `block.completed` is true: overlay green tint using inline style — combine the existing role color background (`roleColor.replace(")", " / 0.2)")`) with a green tint by adding `hsl(var(--success) / 0.15)` as a secondary background layer or adjusting the background color. Reduce text opacity to ~60%. Keep role-color left border unchanged.

The checkbox must not interfere with: resize handle (bottom edge, separate element), inline editing (title input, separate element), drag (stopPropagation on checkbox pointer/click events), or delete button (top-right, separate element). Do not show the checkbox during inline editing mode (`isInlineEditing`).

Note: completed opacity (~60%) must not stack confusingly with `isDragging` opacity-50. When both are true, use only `opacity-50` (the drag state takes visual precedence).

### 5. Add completion UI to DraggableEveningBlock
**Files:** `src/components/calendar/EveningSlot.tsx`

Inside the `DraggableEveningBlock` component, import CompletionCheckbox and wire to `weekStore.toggleEveningBlockCompleted(eveningBlock.id)`. Place checkbox alongside the title. When `eveningBlock.completed` is true: overlay green tint using inline style `hsl(var(--success) / 0.15)` on background, reduce text opacity to ~60%. Keep role-color left border unchanged. The checkbox `stopPropagation` prevents drag activation. Checkbox is always visible, not hidden on hover.

- Click checkbox on an evening block — green tint, faded text. Drag and delete still work
- Refreshing the page persists all completion states
- Completing one item does not affect the same goal in other locations
